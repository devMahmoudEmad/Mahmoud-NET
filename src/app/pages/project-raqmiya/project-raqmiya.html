Engineering Case Study

Raqmiya Digital Marketplace

Full-stack digital marketplace platform built with .NET 8 Web API and Angular 20

Backend Developer + Integration · .NET 8 · Angular 20 · SQL Server · SignalR

Overview

Raqmiya is a comprehensive digital marketplace connecting creators with customers worldwide. Built with .NET 8 and Angular 20, the platform enables creators to sell digital products, courses, and services while providing customers with a secure shopping experience featuring real-time communication and AI-powered capabilities.

My primary contribution was designing and building the entire backend API — RESTful endpoints for authentication, product management, messaging, payment processing, and analytics — using Clean Architecture with separate API, Core, and Infrastructure layers. I also led the Angular-API integration, building typed HTTP services that consumed every backend endpoint, implementing SignalR hubs for real-time features, and supporting the frontend components by wiring them to the API layer.

Business Problem

Digital marketplaces require a robust backend that can handle multi-role user management (Admin, Creator, Customer), secure payment processing, real-time messaging between buyers and sellers, AI-powered content moderation, and comprehensive analytics — all while maintaining data consistency and security. The challenge was to build a scalable API that could serve an Angular SPA and support future mobile clients.

My Role

I worked as the Backend Developer and was responsible for the full API design and implementation. I built RESTful controllers and SignalR hubs, implemented JWT authentication with role-based access, designed the SQL Server database schema with Entity Framework Core, and integrated Stripe payment processing. On the frontend side, I built the HTTP service layer that connected every Angular component to the API, implemented SignalR client integration for real-time chat and notifications, and supported component development by ensuring the API contract aligned with the UI requirements.

Key Features

Core Marketplace: Digital product sales, secure payment processing via Stripe, instant downloads after purchase, advanced search and filtering, and a review and rating system.
Real-time Communication: Live messaging between customers and creators via SignalR, service requests with budget proposals, file attachments in conversations, and read receipts with delivery confirmations.
AI-powered Features: Intelligent chatbot with RAG (Retrieval-Augmented Generation), Google Vision API integration for image safety moderation, knowledge base with document analysis, and smart product recommendations.
Multi-Role System: Admin, Creator, and Customer roles with JWT authentication, comprehensive profile management, and granular access control through route guards and policy-based authorization.
Analytics and Reporting: Revenue analytics with detailed sales and earnings reports, user engagement tracking, product performance metrics, and financial insights with currency support.

Clean Architecture: The backend is structured into three projects — API (controllers, hubs, middleware), Core (entities, interfaces, business services), and Infrastructure (EF Core, repositories, external API clients). This separation keeps business logic independent of framework concerns.
Angular Service Layer: Every API endpoint is consumed through typed Angular services. Components delegate data access to these services, keeping templates clean and making the API contract explicit. SignalR client integration is encapsulated in dedicated chat services.
Real-time via SignalR: Messaging, notifications, and presence indicators use SignalR hubs on the backend with corresponding Angular service clients. The server pushes events to connected clients, eliminating polling and enabling instant updates.

Engineering Decisions

Why .NET 8 with Clean Architecture?
.NET 8 provides the latest performance improvements and language features. Clean Architecture with three projects (API, Core, Infrastructure) ensures the domain logic remains framework-agnostic and testable. New features can be added by extending existing interfaces and services without modifying the core layer.
Why SignalR for Real-time Features?
Marketplace messaging requires instant delivery — polling would be inefficient and slow. SignalR provides persistent WebSocket connections with automatic fallback to Server-Sent Events or long polling when WebSockets are unavailable. The Angular @microsoft/signalr client integrates seamlessly, enabling typed hub method calls from both sides.
Why Stripe for Payment Processing?
Stripe handles PCI compliance, supports multiple payment methods globally, and provides webhooks for event-driven payment workflows. The PaymentIntent API enables secure payment flows where sensitive card data never touches the server, reducing security scope.
How Was Angular-API Integration Structured?
Each backend controller has a corresponding Angular service that provides typed methods for every endpoint. HTTP interceptors attach JWT tokens automatically. Environment-specific API URLs are configured through Angular environment files. SignalR service clients manage connection lifecycle, reconnection, and hub method registration, keeping real-time communication decoupled from component logic.

Lessons Learned

Clean Architecture in Practice

Separating the backend into API, Core, and Infrastructure projects makes the system maintainable and testable. Business logic in the Core layer has no dependency on ASP.NET or EF Core, making it straightforward to unit test without mocking infrastructure concerns.

Real-time Communication Design

SignalR hubs require careful connection management on the client side — handling reconnection, grouping users by conversation, and managing presence state. The Angular SignalR client handles most of this, but you need to design hub method contracts as carefully as REST endpoints.

API-Driven Frontend Development

Building the API contract first (controllers, DTOs, response shapes) and then consuming it from Angular services creates a clean separation. Typed services with RxJS observables make error handling and loading state management consistent across the application.

Third-party Integration Patterns

Integrating Stripe, Google Vision API, and SMTP taught me the importance of wrapping external dependencies behind interfaces. This makes the system testable (you can mock the interface) and swapable (changing providers doesn't ripple through the codebase).
